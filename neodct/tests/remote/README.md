# Fixtures for the update downloader

These drive `neodct/src/test/unit/test_remote.c`, which is the host test for
`lib/nd_remote.c` — the port of `System/core/UpdateService/remote.py`.

**No test that uses these has ever made a network request, and neither has
`nd_remote.c`.** The transport is a spawned `curl`, so the test replaces the
executable rather than the code: `fake-curl` goes first on `PATH` and the
library finds it with its own `PATH` walk, spawns it with `nd_proc_spawn()`,
opens the same three pipes, and parses the same HTTP framing. Nothing in the
library is stubbed, compiled differently, or given a test-only branch.

## The files

| File | What it is |
| --- | --- |
| `fake-curl` | The stand-in. Reads a scenario out of `$NDCURL_DIR`, writes headers to its `-D` target, the body to stdout, and curl's own complaints to stderr, exiting with curl's own codes (0, 6, 18). Its header comment lists every control file. |
| `releases.json` | A GitHub `/releases` listing, four releases, both platforms, deliberately **not** in version order. |
| `releases-qemu-only.json` | A release carrying only the other platform's asset — an upload still in progress. |
| `releases-insecure-url.json` | A newest release whose asset URL is `http://`. |
| `one-object.json` | What `/releases/latest` returns: an object, not a list. |
| `not-json.html` | What a captive portal sends instead. |
| `package.bin` | 4000 bytes of `i % 251`, the same pattern `test_update_remote.py` uses, so a wrongly reassembled download shows up as a wrong **byte** and not merely a wrong length. |
| `version_order.txt` | 625 `candidate\|installed\|is_newer` triples, **generated by running the real `remote.py`**. |

## How the expectations were established

Not by reading the C and agreeing with it. `remote.py` was imported and run
against these exact fixture bytes, with only `remote._open` replaced, and its
answers were recorded:

```python
import io, os, sys
sys.path.insert(0, "neodct/overlay/NeoDCT")
from System.core.UpdateService import remote

class R(io.BytesIO):
    status = 200
    def __enter__(self): return self
    def __exit__(self, *a): self.close(); return False

data = open("neodct/tests/remote/releases.json", "rb").read()
remote._open = lambda url, timeout=None, headers=None: R(data)
print(remote.latest("luckfox-armv7"))
print([r["version"] for r in remote.all_releases("luckfox-armv7")])
```

What it said, and what `test_remote.c` therefore asserts:

| Input | `remote.py` |
| --- | --- |
| `latest("luckfox-armv7")` on `releases.json` | version `0.3.11a`, size `4000` |
| `latest("qemu-aarch64")` on `releases.json` | version `0.3.11a`, size `4001` |
| `all_releases("luckfox-armv7")` on `releases.json` | `0.3.2a`, `0.3.11a`, `0.3.10a` — publication order, not version order |
| `latest("luckfox-armv7")` on `releases-qemu-only.json` | `NoRelease: no release carries UPDATE-luckfox-armv7.ndsw` |
| `latest(...)` on `not-json.html` | `NetworkError: GitHub sent something that is not JSON` |
| `latest(...)` on `one-object.json` | `NetworkError: GitHub did not send a list of releases` |
| `latest("luckfox-armv7")` on `releases-insecure-url.json` | version `0.3.12a`, url `http://insecure.example.invalid/pkg.ndsw` |

`version_order.txt` was produced the same way, over every ordered pair of
twenty-five version strings including `0.3.9a` / `0.3.10a`, `0.4.0a` /
`0.3.99a`, tags that kept their `v`, versions with `-` and `_` separators,
and surrounding whitespace. Regenerate it with the loop at the top of the
file if `remote.py` ever changes; do not hand-edit it.

## The one place the C deliberately disagrees

`releases-insecure-url.json`. `remote.py` offers `0.3.12a` and its `http://`
asset URL; `nd_remote.c` skips that entry and offers `0.3.8a` instead,
because a rootfs must not be fetched over plaintext and `--proto-redir
'=https'` would refuse it a moment later anyway. The divergence is in the
direction of offering an **older** release, never a worse one, and
`test_an_insecure_asset_url_is_skipped()` asserts it so it cannot drift back.
