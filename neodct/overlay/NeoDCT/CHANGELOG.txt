# NeoDCT OS Changelog

0.4.3a
Two engineering apps for hardware you can plug in.

Both answer a question the phone could not answer about itself before: is
the microphone working, and is the Bluetooth dongle alive. Neither needs a
serial cable or a laptop -- you plug the thing in and look at the screen.

Added
- MicTest, in Engineering. It lists every capture device the kernel is
  offering, by name, and draws a live waveform of whatever the one you
  pick is hearing. Speak and the line moves; silence draws a flat line
  rather than nothing, so a dead microphone looks like silence instead of
  like a crashed app.
  It lists CAPTURE devices only. A phone with a USB sound card in it has
  at least two, and the one that can record is not always the one ALSA
  calls "default" -- picking the wrong one is silence with no error, which
  is the failure this app exists to end.
- Bluetooth, in Engineering. Finds the adapter, reports its address, and
  scans for nearby devices. Driven straight through the kernel's own HCI
  interface, so there is no Bluetooth daemon on the phone and nothing
  running when the app is closed.
- Firmware for the TP-Link UB500 (an RTL8761BU), which carries none of its
  own and is a dead adapter without it. It ships in lib/firmware/rtl_bt,
  with the Realtek licence beside it as that licence requires.

Changed
- Non-free firmware now lives in ONE place in the source tree,
  neodct/nonfree/, beside the Rockchip DDR blob, and is copied into the
  image by a build step rather than sitting in the overlay. What
  proprietary code this phone runs is now answered by listing one
  directory.

0.4.2a
Messages can look like a chat app now, and Remote Shell finally lets you in.

Settings has a new entry, Messages Style, with two choices. Classic is
the inbox-and-outbox the phone has always had, and it is still what you
get if you never touch the setting. Chat replaces it with a list of
conversations and a transcript of bubbles, the way a phone made this
century does it.

Added
- Messages Style, in Settings. Classic or Chat.
- Chat opens on your conversations rather than on a menu: one row per
  person, their name from the phone book, and the last thing either of
  you said underneath it as a preview. An unread conversation is marked
  with a *, and "You:" in front of a preview means the last word was
  yours. Newest conversation first.
- New Message sits at the top of that list and opens the same composer
  Classic uses.
- The conversation list gives each row two clear lines, so a contact
  whose name has a descender -- a p, a g, a y -- no longer has the
  message preview drawn through the tails of it.
- Opening a conversation shows it as bubbles -- yours filled and on the
  right, theirs outlined and on the left. Up and Down walk from the
  message box at the bottom back through the transcript.
- Delete and Forward on any single message, in BOTH styles. Forward
  opens the composer with the message already typed in, so you only
  have to pick who it goes to. This replaces the old "Erase", which
  could only do the one thing.
- A tool for putting fake conversations on a development phone,
  System/engineering/tools/debug_sms_seed_chats.py -- several people,
  both directions, and contacts to go with them.

Changed
- Writing a reply from inside a conversation now says WHO it is to in
  the header, instead of just "Write". The input-mode indicator sits at
  the other end of the same row, so one glance gives you both. Starting
  a new message or forwarding one still says "Write" -- there is no
  recipient to name yet.

Fixed
- Sent messages are now saved. The phone used to hand a text to the
  modem and forget it ever existed, which meant the screen called
  "Outbox" never contained anything you had actually sent. It does now,
  in Classic as well as in Chat.
- Remote Shell lets you in. It has never worked reliably, for two
  reasons that both look identical from a laptop -- a refused
  connection, or a rejected key -- and neither of which was your
  setup.
- The phone starts its ssh server at boot, before the network scripts
  have finished, and binding to itself fails outright when loopback is
  not up yet. It gave up there and nothing ever started it again, while
  the tunnel out to the relay retried its way to a working connection
  and held it. So the relay showed a phone dialled in, every hop
  worked, and the connection arrived at a port with nothing behind it.
  Whether it happened at all came down to which won the race that boot,
  which is why it worked sometimes. The ssh server now retries the same
  way the tunnel always has.
- A half-made host key is no longer kept forever. Generating one wants
  randomness the phone has not gathered yet on a first boot, and an
  interrupted attempt leaves an empty file behind; the phone took that
  file as proof it had a key, and from then on the ssh server refused
  to start on every boot, for good. It now checks that the key is one
  it can actually load, and makes a new one when it is not.

0.4.1a
The Music app grew a library.

It used to list the raw filenames it found on the card, in the order the
directory walk happened to produce them, and there was no way to change
the volume at all. Now it opens on a menu: Artists, Albums, Songs,
Folders, Volume.

Added
- Browse by artist, album or song. The app reads the ID3 tags off every
  track on the card and groups them properly: artists in alphabetical
  order, an artist's albums oldest first, and an album's tracks in
  TRACK NUMBER order rather than filename order -- so a record whose
  files are called 01.mp3, 02.mp3 and a-side.mp3 finally plays in the
  order it was recorded in.
- Compilations stay in one piece. A track's album artist, where it has
  one, decides which artist it belongs to, so a "Various Artists" record
  is one entry with one album under it instead of forty artists with one
  track each.
- Volume, on a ten-step scale that is even in loudness rather than in
  amplitude. Up and Down while a track is playing open a full-screen
  scale, and the level is remembered between sessions. It is applied to
  the audio itself, which means turning the music down does NOT turn the
  ringtone down -- a phone that stops ringing because you were listening
  quietly is a phone that loses you a call.
- Picking a track now plays the list it came from, and moves on to the
  next track when one ends, instead of dropping back to the menu every
  three minutes. Left and Right skip.

Changed
- The tag reader learned four more frames -- album artist, track number,
  disc number and the recording year -- which is what the grouping and
  the ordering are built out of.
- Reading the tags off a full card takes a moment, so it happens the
  first time you choose Artists, Albums or Songs, behind a progress bar
  that Clear cancels. Folders is still instant and still shows exactly
  what it always showed: the filenames, in the old order. Nothing that
  worked before was taken away.

Fixed
- A file with no tags, or one that has gone missing since the card was
  scanned, no longer stops the scan. It is listed under Unknown Artist
  with its filename as the title.
- The unit tests build again on a toolchain that pairs a recent glibc
  with -O2, where a cast to void is not enough to ignore write()'s
  result.

0.4.0
The whole operating system has been rewritten in C.

Every line of it -- the main loop, the framebuffer, all fourteen widgets,
the modem, the phone book, the dialler, the games, the browser launcher,
the update system -- was rewritten from the Python original in four days,
by a fleet of Claude agents working in parallel on separate branches. Ten
of them were writing into the same source tree at once; the build's
source lists are wildcards rather than hand-written for exactly that
reason. 109 commits, about 141,000 lines of C and headers.

And you cannot tell. That was the point. 48 screens rendered by the new C
build are compared against captures from the Python one and every single
one matches BYTE FOR BYTE -- not "looks the same", the same pixels. The
menus, the fonts, the spacing, the blinking cursor, even a couple of
bugs that were faithfully carried across because changing them would
have changed the picture.

Changed
- The whole operating system is now written in C. Everything you see on
  screen -- the menus, the phone book, the dialler, the text boxes -- is
  drawn by new code that produces the same picture, pixel for pixel, as
  the version before it. 48 screens are checked against the old ones
  automatically, and every one of them matches exactly.
- The phone uses about a third of the memory it used to. Sitting on the
  home screen it was using around 20 MB and now uses under 8 MB, which
  is most of the reason for doing this at all: there is finally room to
  add things.
- Every app is now real C. Nothing is left running the old Python.
- Apps now run as separate programs instead of inside the system itself.
  If an app goes wrong it can no longer take the phone down with it --
  you get a crash screen and you are back at the menu, and the modem,
  the clock and the battery never stop running.
- A call now interrupts whatever app you are in. It could not always do
  that before; a game that never checked for keypresses would quietly
  miss the call.
- Every app can now tell when you are holding a key down, so holding up
  or down scrolls a list instead of moving one line per press.

Fixed
- Settings were being written back to storage on every single read, from
  the modem and battery code that runs constantly. On a phone that keeps
  everything in flash memory that wears the chip out for no reason.
- The screen driver was being shipped as a prebuilt file that nobody
  rebuilt. It is now compiled from its source with everything else.

0.3.14a
Fixed
- Sound comes out of the USB sound card instead of the socket on the board
  that nothing is plugged into. The phone was playing everything into a
  speaker that does not exist.
- The two programs a phone call needs to carry sound were missing from the
  phone altogether. They were built but never installed, so a call could
  never have had audio in either direction.

0.3.13a
Fixed
- Downloading an update over mobile data now carries on where it stopped.
  The phone used to throw away everything it had downloaded whenever the
  connection dropped, so on a slow signal the download could never finish
  however many times you tried. It now keeps what it has and asks only
  for the rest.
- The phone waits longer for a slow download before giving up. Twenty
  seconds is right for checking whether an update exists and far too
  short for fetching one.
- The phone now waits and tries again when mobile data drops out during a
  download, instead of giving up straight away. On a weak signal the
  connection can disappear entirely for a few seconds, and it used to use
  up every retry inside that gap.
- Looking up addresses recovers faster when one of the carrier's name
  servers stops answering.
- The phone notices when mobile data drops and dials again by itself. It
  used to connect once at start-up and never check afterwards, so a
  connection lost an hour later stayed lost until the phone was
  restarted. Calls kept working throughout, which made it look like only
  the internet was broken.

0.3.12a
Fixed
- Remote Shell would not let you in, even with the right key. It reported
  the same "permission denied" a wrong key gives, so there was nothing to
  go on. The phone was refusing to read its own list of allowed keys
  because of the permissions on the folder above it, which a fresh
  install leaves open.

0.3.11a
Added
- Remote Shell, in the engineering tools: reach this phone over the
  internet with ssh and sftp, from anywhere, without opening it up. The
  phone calls out to a relay you run, so it works from behind a mobile
  network that will not accept incoming connections. Off until you turn it
  on. Set-up instructions are in docs/REMOTE_SHELL.md.

Fixed
- The phone reported the previous version number. It was running the right
  software and saying the wrong thing about it.
- Long titles no longer run underneath the number in the top right corner.

Changed
- Remote Shell sits next to Linux Shell in the engineering list, where it
  belongs.

0.3.10a
Fixed
- Updates install. The phone used to copy the whole system onto its own
  small storage before restarting, and there was never enough room for it
  there, whatever size card was in the phone. It now installs the update
  straight from the card and copies nothing.
- Update can find updates again. "Look online" reported that nothing was
  published no matter what had been released, because the phone asked for
  the newest finished release and every NeoDCT release is marked as a
  test build.
- Recovery can read cards that are not FAT32. Large cards are usually
  exFAT, and recovery said there was no card in the phone at all.

Note
- 0.3.9a could not be installed, so everything listed under it arrives
  here: the clock, predictive typing, and the security-warning fix. This
  version has to be flashed over USB. After it, updates work from the
  phone.

0.3.9a
Added
- The phone sets its own clock. It starts from the date the software was
  built and corrects itself over the internet once there is a signal.
- Predictive typing. Press # until a pencil appears next to "abc", then
  press each letter's key once and the phone guesses the word. Press * for
  the next word the same keys could spell, and clear to take one key back.
  The guess is underlined until you type a space, so you can see what is
  still a guess. It knows 315,000 words, "NeoDCT" among them.

Fixed
- Websites no longer report security warnings. The phone believed it was
  1970, and no certificate on the internet is valid that far back.
- Update can find updates again. "Look online" reported that nothing was
  published no matter what had been released, because the phone asked for
  the newest finished release and every NeoDCT release is marked as a
  test build. This is the first version that can see them; older ones
  cannot, so this one has to be installed from a card.

0.3.8a
Added
- Downgrade, in the engineering tools: lists every published release and
  installs the one you pick, so you can go back to an older version when a
  newer one gives you trouble.

0.3.7a
Added
- The phone can update itself over the internet. Update now offers to look
  online when there is nothing on the card, downloads the release built for
  this phone, and installs it the same way a card update is installed.
- The browser reports itself in purple, and says what it is doing: the
  pages it opens, how much memory and processor it is using together, and
  any security warnings about a site, in red.

Changed
- The startup picture now appears at the end of start-up, after the system
  messages, rather than before them.

0.3.6a
Added
- The serial log opens with the NeoDCT name and version, and every service
  now has its own colour. The modem is blue, the system green, anything
  that failed is red.
- The modem talks to the serial console as it works. It used to keep
  everything it knew in a file on the phone.

Fixed
- Mobile data. Each dial attempt was taking a connection slot from the
  modem and never giving it back, so after enough tries the modem stopped
  answering until it was power-cycled.

0.3.5a
Changed
- The phone now tries the modem's QMI data path first. It used to work
  through every APN on the older path before reaching the one that
  connects, which cost minutes on each start-up.

0.3.4a
Fixed
- Mobile data now connects. The QMI dial dropped the carrier's session the
  moment it finished setting it up, and only ever offered one APN.
- The phone no longer waits fifteen seconds at every boot for an ethernet
  port it does not have.
